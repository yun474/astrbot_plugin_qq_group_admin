## ✨ 群管功能

| | 功能 |
| --- | --- |
| 🔇 **禁言与解禁** | 多成员操作、组合时长、默认时长与禁言状态查询 |

## 🚀 安装与使用

最低要求 **AstrBot 4.25.3**，并使用该版本或更新版本配套的 WebUI；插件已在 **AstrBot 4.26.8** 上完成配置加载、校验和面板逻辑验证。

在 AstrBot 插件管理中通过[仓库链接](https://github.com/yun474/astrbot_plugin_qq_group_admin)安装，或导入插件 ZIP。也可将插件目录放入 `data/plugins/` 后安装 `requirements.txt` 中的依赖并重载。插件使用 `regex` 为进群正则匹配提供超时限制，AstrBot 正常安装流程会自动安装该依赖。

使用前请确认：

1. 使用 `qq_official` 或 `qq_official_webhook` 适配器，启用群/C2C 事件。
2. 机器人是目标 QQ 群的管理员，并已获得对应群管理接口权限。
3. 使用审批按钮需具备自定义 Markdown/按钮权限；Webhook 需订阅 `INTERACTION_CREATE`。

**在群里 @机器人后，直接发送下表指令，无需额外添加 `/`。** QQ 快捷指令自动补上 @机器人时，同样只需填写指令正文。插件功能菜单中的快捷链接也不带固定前缀，点击填入后需手动发送。

如果习惯使用前缀，请在 AstrBot 当前会话使用的配置中设置「唤醒词」，例如 `!`，再发送 `!群管帮助`。`/` 只是可选的唤醒词之一；未配置 `/` 时，`@机器人 /群管帮助` 也可能无法匹配指令。QQ 群内仍需通过 @机器人等平台支持的方式，让消息送达机器人。

| 指令 | 用途 |
| --- | --- |
| `禁言 @用户 [时间]` | 禁言一个或多个成员，省略时间默认 **1 分钟** |
| `解禁 @用户` | 解除成员禁言 |
| `禁言状态` | 查看全员禁言规则及被禁言成员 |
| `添加群管 @用户` / `删除群管 @用户` | 管理本群插件群管 |
| `群管列表` / `群管帮助` | 查看群管名单与使用帮助 |
| `群管功能` | 查看功能开关；点击状态填入修改指令，发送后生效 |

时间支持 `30秒`、`10分`、`2小时`、`1天2小时`，纯数字按分钟；`0`、`解除`、`解禁`表示解除禁言。默认时长可在配置中修改。

> 禁言仅适用于普通成员；全员禁言规则目前只提供查询，不提供设置。

一次最多处理前 10 名被艾特的成员。多人禁言或解禁时，某个成员操作失败会继续处理其余成员，并汇总成功人数、失败成员和原因。

## 📨 入群申请：两种人工审批方式

申请卡片展示昵称、时间、来源、风险提示和验证内容，隐藏成员 OpenID 与申请 ID。

### ① 点击回调按钮

**点击后直接审批并在群内反馈，不需要再发送指令。**

| 按钮 | 权限 |
| --- | --- |
| 群管同意 / 群管拒绝（第一行） | QQ 原生群主、群管理员，由 QQ 的「仅管理者可操作」按钮权限控制 |
| 授权同意 / 授权拒绝（第二行） | 发卡时的 AstrBot 管理员和本群插件群管，QQ 限制指定用户点击，插件再实时复核名单 |

点击拒绝按钮不填写理由。成功处理后该申请的所有按钮失效；按钮、引用回复和 LLM 工具共享处理锁，处理中的重复审批不会重复提交。

### ② 引用通知回复

回复**机器人发出的原申请通知**，发送 `同意`、`通过`、`拒绝` 或 `拒绝 理由`，例如 `拒绝 未完成入群验证`。

引用审批通过 QQ 原消息 ID 或引用索引定位：发送通知时保存 `ext_info.ref_idx`，引用时匹配 `message_scene.ext` 中的 `ref_msg_idx` 或引用元素的 `msg_idx`。只匹配当前平台、当前群的待审记录，并检查操作者权限。支持不带前缀，也支持当前会话在 AstrBot 中配置的唤醒词，例如 `!同意`、`!拒绝 理由`；兼容旧用法 `/同意`、`/拒绝 理由`。回调按钮直接审批，不受唤醒词影响。

> 索引缺失、冲突或无法匹配，或申请已处理、过期时，插件会明确提示，不再转入默认 LLM。旧通知没有保存引用索引时仍可通过原消息 ID 审批，无法匹配则请使用审批按钮。按钮发送失败时通知会降级为纯文本，也会保存发送响应中的引用索引。插件不再从引用正文提取申请 ID。

2.6.0 已移除申请编号、编号审批指令和 `/群申请归零`；旧通知上的编号按钮不再生效。LLM 申请审批工具仍单独保留。


## 🔎 关键词自动管理

在配置面板「② 全局与分群配置」中，展开全局配置或目标群 UMO，再进入「⑧ 关键词管理」。入群自动审批、消息违禁词禁言和撤回均默认关闭。进群白词、黑词和消息违禁词默认使用**普通文本包含匹配**；进群白黑词另可选择正则匹配。默认忽略大小写和词条首尾空白，空词条不生效。

### 入群白词与黑词

开启「入群关键词自动审批」后，只检查入群申请中用户填写的**问题回答**：

- 任一回答包含白词：自动同意；包含黑词：自动拒绝。每条规则单独匹配每个回答，不把多个回答拼接。
- 同时命中两类词（包括不同回答分别命中）时，按「优先规则」处理：默认**黑词优先**，可改为**白词优先**。
- 未命中、没有回答或对应词表为空时，不自动决定，继续原来的人工审批流程。问题文字、昵称和单独的验证消息不参与匹配。
- 自动审批成功后不再发送待审卡片，已有待审映射会清理；失败仅记录日志，并在申请通知开启时发送人工审批通知。QQ 已自动通过的申请仅发送结果通知，不再保留待审记录或审批按钮。插件完成审批后会保存完成标记，在保留期限内阻止重复事件再次审批或生成待审卡片，重载后仍然生效。

默认「包含匹配」只需填写词语：例如填 `广告`，回答 `我来发广告` 就会命中；`a.b`、`C++`、`[` 都按普通文字处理，无需转义。旧词表原样保留。

需要表达式时，将「进群匹配模式」设为「正则匹配」，再按每条一个正则填写，不加 `/.../` 分隔符。例如 `^(天文|摄影)爱好者$` 匹配完整回答，`广告|推广` 匹配其中任一种内容。默认忽略大小写，可用 `(?-i:ABC)` 对局部区分大小写；`\d` 和 `\D` 等转义本身有不同含义，添加和删除时按原样区分。切换模式不会改写词表，请检查现有词条在新模式下的含义。

正则模式下，群内添加或切换到该模式时校验语法；面板保存的无效规则或一次匹配超过 50 毫秒时，本次停止自动审批，记录日志，并在申请通知开启时转人工处理，不会跳过有问题的黑词后自动放行。

此功能独立于「入群申请通知」「入群申请审批」开关，仍遵守群环境白名单和会话插件启停设置。

### 消息违禁词禁言与撤回

开启「违禁词自动禁言」并填写词表后，群消息正文包含任一违禁词，就按「违禁词禁言时长」禁言发送者，默认 **10 分钟**。时长支持 `30秒`、`10分`、`2小时` 等，纯数字按分钟；必须大于 0，且不超过「⑦ 安全限制」中的最长秒数。

「违禁词消息撤回」使用同一份消息违禁词表，和禁言开关独立，可只撤回、只禁言或同时开启。命中后优先尝试撤回；撤回失败仍会尝试禁言，禁言参数错误也不影响撤回。

[QQ 官方撤回接口](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages_message_id.delete.html)要求机器人是群管理员，目标为普通成员发送、且未超过 **2 分钟**的消息。插件直接使用当前 AstrBot 事件的 `message_obj.message_id`（原始消息的 `d.id`），不会取引用消息 ID，也不保存触发消息的正文或 ID。缺少 ID 时跳过撤回并记日志。此功能不需要插件保存聊天记录；AstrBot 本身或其他插件的记录行为由各自配置决定。

**成功、失败都不发送群提示**，失败仅记日志；命中的消息会停止后续指令和 LLM 处理。只检查本条消息的文字，不检查引用原文、图片或语音，机器人自身消息跳过。有权限的群管通过 `群管功能` 查看或调整配置时不会因指令内的词条被误禁言；有权限的群管引用本群有效待审申请发送审批指令时，会优先审批，避免拒绝理由中的违禁词触发禁言；普通聊天不按管理员身份豁免，能否禁言由 QQ 接口权限决定。

检测范围是机器人实际收到并进入 AstrBot 插件处理流程的消息；QQ 未投递的消息无法检查。它不依赖本插件的「禁言指令」或 LLM 工具开关。

开启分群配置后，功能开关、词表、进群匹配模式、优先级和禁言时长都可以独立设置；群内修改只影响当前真实群 UMO，并自动保存到面板的群列表。全局模式下，修改仅限 AstrBot 管理员，群管仍可查看。

`群管功能` 展示白词、黑词、违禁词的数量和预览，并提供查看、添加、删除、切换匹配模式、切换优先级、修改时长的快捷链接。点击只填入指令，补全内容并发送后才保存。词表每页 10 条。

| 指令示例 | 效果 |
| --- | --- |
| `群管功能 入群关键词审批 开启` | 开启回答白黑词审批 |
| `群管功能 违禁词禁言 开启` | 开启消息违禁词禁言 |
| `群管功能 违禁词撤回 开启` | 开启消息违禁词撤回，可与禁言独立使用 |
| `群管功能 进群白词 添加 天文` | 默认回答包含“天文”即命中白词 |
| `群管功能 进群黑词 添加 广告` | 默认回答包含“广告”即命中黑词 |
| `群管功能 进群匹配模式 设置 正则匹配` | 将进群白黑词切换为正则匹配，可设回“包含匹配” |
| `群管功能 违禁词 添加 bad phrase` | 添加完整词条，支持空格 |
| `群管功能 违禁词 查看 2` | 查看第二页，点击对应删除链接可填入删除指令 |
| `群管功能 违禁词 删除 bad phrase` | 删除对应完整词条 |
| `群管功能 违禁词 清空 确认` | 清空该词表 |
| `群管功能 白黑词优先级 设置 白词优先` | 调整同时命中时的处理规则 |
| `群管功能 违禁词时长 设置 30分` | 调整禁言时长 |

`进群白词`、`进群黑词`、`违禁词` 都支持上述查看、添加、删除和清空操作。包含模式添加同名词（忽略大小写）不会重复保存；正则模式按原样区分词条。指令前缀遵循 AstrBot 的唤醒词设置。

## 🗝️ 权限与开关

| 操作 | AstrBot 管理员 | 插件群管 | QQ 群主/管理员 | 普通成员 |
| --- | :---: | :---: | :---: | :---: |
| 禁言、解禁、状态查询、人工审批 | ✅ | ✅ | ✅ | — |
| 添加/删除插件群管 | ✅ | — | 可配置，默认关闭 | — |
| 查看/修改本群功能（分群模式） | ✅ | ✅ | ✅ | — |
| 修改全局功能开关 | ✅ | — | — | — |
| 查看群管名单与帮助 | ✅ | ✅ | ✅ | ✅ |

插件群管按群保存，使用 QQ 官方机器人中的成员 OpenID。

### LLM 唤醒人权限

「⑥ LLM 群管工具 → **严格审查唤醒人权限**」默认**关闭**：

- **关闭**：由模型决定调用，以机器人权限执行；不按唤醒人身份拦截。
- **开启**：五个工具均校验真实唤醒人的群管权限，普通成员无法调用，查询工具也不例外。

该开关可在目标群配置中独立设置。工具结果交回模型自然回复；“关闭禁言和解禁的固定成功提示”只影响人工指令的成功提示，不影响错误提示和模型回复。

### 全局与分群配置

配置面板按层级展开：

- **关闭分群**：显示原有的全局配置，各群统一使用。已有群条目会保留。
- **开启分群**：显示 UMO 列表，每个条目可展开设置群管权限、指令、申请审批、成员通知、LLM 工具、安全限制和完整关键词规则。关闭具体关键词功能时，对应的词表和时长会收起，内容不删除。
- **群内首次修改**：自动建立当前群的 UMO 条目，复制当时的全局配置，再保存本次修改。之后该群使用独立配置。
- **面板手动新增**：模板采用插件默认值，请填写真实群 UMO 并核对各项后保存。未建条目的群继续使用原全局配置；删除条目也会恢复这个行为。
- **群身份**：使用 `平台ID:GroupMessage:真实群ID`，与发送者无关。开启 AstrBot 独立会话也不会把群配置存到用户名下。群管发送 `群管功能` 可查看本群 UMO；群白名单同样使用这个 UMO，不要填写独立会话下 `sid` 返回的用户 UMO。
- **面板同步**：群内修改立即写入 AstrBot 插件配置文件，重新打开面板即可看到。已经打开的表单不会自动刷新；群内修改后先重新打开面板再编辑，避免旧表单覆盖新值。面板保存后由 AstrBot 重载插件生效。

群白名单和待审记录保留天数仍是全局项。保留天数在关闭分群时的全局入群申请配置中设置。分群模式下修改全局配置不会覆盖已有群条目。

### 旧配置迁移

首次加载会把旧全局配置和 `state.json` 中的分群开关迁入新面板：先复制当时全局有效值，再叠加各群的旧开关。迁移前配置及旧分群记录保存在插件数据目录的 `group-config-before-v2.json`；旧 `state.json` 中的记录也保留，后续不再作为新分群配置的写入目标。迁移标记确保删除群条目后，重启不会把它从旧存储重新导入。

**无法自动还原的情况**：旧版在独立会话模式下可能把用户 ID 当作群 ID 保存，原记录没有所属群信息。检测到当前启用独立会话、且无法从待审记录确认群归属时，对应条目会标为待确认并暂不应用。请在真实群发送 `群管功能` 获取 UMO，修正条目后开启「已确认 UMO 属于目标群」。如果过去开启过独立会话、后来又关闭，历史状态无法从配置判断，也请人工核对旧 UMO。云云不会把用户 ID 猜成某个群。

迁移或群内配置保存失败时不会保留未落盘的新配置。

面板的开关联动显示使用 `condition`，自 AstrBot **4.0.0** 支持（[上游 #2433](https://github.com/AstrBotDevs/AstrBot/pull/2433)）；分群列表使用 `template_list`，自 **4.10.4** 支持（[上游 #4208](https://github.com/AstrBotDevs/AstrBot/pull/4208)）；折叠条目显示 UMO 使用 `display_item`，自 **4.25.3** 支持（[上游 #8228](https://github.com/AstrBotDevs/AstrBot/pull/8228)、[4.25.3 发布记录](https://github.com/AstrBotDevs/AstrBot/releases/tag/v4.25.3)）。因此插件声明最低要求 **4.25.3**，已核对该版本的配置组件与所用核心接口；**4.26.8** 是验证版本，4.25.3 尚未进行真实 QQ 群联调。

AstrBot 当前会话的插件启停设置同样生效：如果当前配置未启用本插件，或已在会话内禁用它，自动通知和旧申请卡片的审批按钮也会停止工作。

## 👋 进退群通知

欢迎和退群通知分别提供开关与模板：

| 占位符 | 进群 | 退群 |
| --- | --- | --- |
| `{member_at}` | 艾特新成员 | 显示 OpenID，无法艾特 |
| `{member_avatar}` | 显示成员头像 | 显示成员头像 |

欢迎文案可以写成 `欢迎 {member_at} 加入群聊！`；退群文案可以搭配 `{member_avatar}` 与 `有成员退出了群聊。`。头像不可用时会省略，Markdown 发送失败时降级为普通文本。

## 💾 数据与备份

本地数据保存在 `data/plugin_data/astrbot_plugin_qq_group_admin/state.json`，包含插件群管名单、迁移前保留的旧分群开关，以及入群申请事件中的昵称、OpenID、验证内容、消息引用和审批按钮映射。新的群配置和词表保存在 AstrBot 插件配置文件的 `group_management.groups` 中，全局设置保存在 `group_management.global_settings` 中。待审映射与审批完成标记默认保留 30 天，成功审批后移除对应待审内容，只保留平台 ID、群 OpenID、申请 ID 和完成时间用于去重；过期记录在加载或查找、写入等操作时清理，并非定时删除。群管名单和群配置会持续保存；群管名单的批量修改一次保存，写盘失败时本次修改全部回滚并提示失败。备份时请同时备份插件配置文件与插件数据目录。

调用 LLM 申请列表工具时，申请内容和审批所需 ID 会作为工具结果交给 AstrBot 配置的模型服务。人工审批卡片会在目标群展示申请内容。

备份或恢复前先停用插件，再复制或替换 `state.json`。若文件格式损坏，插件会将原文件保留为同目录下的 `state.corrupt-随机标识.json`，在日志中提示路径，并以空状态启动：原插件群管和旧申请映射暂不生效；已迁移到插件配置文件的群配置不受此文件损坏影响。修复备份内容后可停用插件，将其恢复为 `state.json` 再启用。读取失败或无法保留损坏文件时会停止加载，避免覆盖原数据。损坏备份不会自动清理。

需要清除本地数据时，请先停用插件，再删除上述状态文件及不再需要的损坏备份；这不会撤销 QQ 中已执行的禁言或审批，也不会删除群消息及模型服务已接收的数据。
